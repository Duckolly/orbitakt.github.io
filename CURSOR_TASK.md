# Задача для Cursor: внедрение диагностики в Android-приложение «Движ»

## Текущее состояние

В ZIP `dvizhoff` присутствует только статический сайт. В нём уже реализованы
локальный веб-логер (assets/diagnostics.js), кнопки экспорта/очистки в support.html,
а также GitHub Pages publish workflow. **Не пытайся диагностировать шагомер
с помощью сайта:** у сайта нет доступа к системному сенсору Android.

Для выполнения этой задачи нужен отдельный checkout **исходников Android-приложения**
с Gradle, manifest, сервисом подсчёта и экраном настроек.

## Задачи для Cursor

1. Изучи фактический стек Android-приложения. Запиши HEAD, versionCode,
   minSdk, targetSdk, используемые датчики, путь UI настроек и реальный
   failure branch с ошибкой «Подсчёт остановлен из-за ошибки датчика,
   доступа или хранения». Ничего не переписывай наугад.
2. Используй `android/LocalDiagnosticLogger.kt` только если проект на Kotlin,
   адаптируй package и логику подключения. Проверь потокобезопасность,
   отказоустойчивость, retention, перезапуск процесса и экспорт через FileProvider.
   Никаких аналитических SDK или автоматической отправки на сервер.
3. Инструментируй service lifecycle: start requested, permission state,
   foreground start, registerListener result, sensor availability,
   step sensor event and baseline reboot detection, persistence result,
   stop reason and recovery. Не логируй сами сырые количества шагов,
   имена, координаты и пользовательский текст по умолчанию.
4. Раздели текущий общий текст ошибки на стабильные диагностические коды:
   STEP_PERMISSION_MISSING, STEP_SENSOR_UNAVAILABLE,
   STEP_LISTENER_REGISTER_FAILED, STEP_STORAGE_WRITE_FAILED,
   STEP_FOREGROUND_SERVICE_STOPPED, STEP_COUNTER_RECOVERED.
   События отсутствия шагов без движения не считать ошибкой сенсора.
5. Добавь UI в настройках: экспорт ZIP через Sharesheet,
   удаление локальных логов, пояснение про ручную передачу и приватность.
6. Проверь частные сценарии: разрешение отозвано, нет датчика,
   экран заблокирован, приложение убито ОС, телефон перезагружен,
   энергосбережение, ошибка БД, повторный запуск сервиса.
7. Добавь unit / instrumentation тесты и попробуй собрать приложение.
   Не заявляй о прохождении тестов на Android-устройстве без реального прогона.

## Критерии приёмки

- Дневной шагомер не выключается из-за сбоя самого логгера.
- Для каждого штатного отказа хранится код, timestamp UTC, component,
  app version, Android API и обезличенные сведения о состоянии.
- Log ring buffer ограничен по размеру и не содержит ПДн по умолчанию.
- Поддержка может запросить отчёт, но он передаётся только пользователем.
- Данные шагов не меняются как побочный эффект интеграции.
- Итог Cursor: changed files, tests, root cause или unresolved cause,
  reproducer, следующее действие, готовый APK при успешной сборке.
